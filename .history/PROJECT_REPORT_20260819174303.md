# Project Report: Java Student Management System

## 1. Introduction
The Java Student Management System is a desktop-based application developed to manage academic records for students, departments, instructors, courses, and enrollments. The system is designed using object-oriented programming principles and provides a command-line interface for operations such as adding records, updating student information, recording marks, and exporting transcripts.

The project demonstrates core Java concepts such as classes, inheritance, abstraction, encapsulation, file-based persistence, and multithreading. It is a practical solution for managing student data in an academic environment.

---

## 2. Project Objective
The primary goal of the project is to create a simple but functional student information system that supports the following responsibilities:

- Manage department records
- Register and update student profiles
- Add instructors and course details
- Enroll students in courses
- Record marks and calculate GPA
- Save and retrieve data from local files
- Export student transcripts asynchronously
- Maintain data automatically with a background save task

---

## 3. Scope of the System
The project covers the academic workflow of a university or college office, including:

- Student administration

## 5. System Architecture and Design
The system follows an object-oriented architecture with separate classes for each key domain entity.

### 5.1 Core Design Principles
- Encapsulation: Data fields are protected using private access and controlled through getters and setters.
- Inheritance: Student and Instructor inherit common attributes from the Person class.
- Abstraction: Person and AcademicRecord define common behavior for inherited classes.
- Modularity: Each class is responsible for a distinct part of the project.
- Persistence: Data is stored in local text files instead of a database.
- Concurrency: Background threads handle auto-save and transcript export tasks.

---

## 6. Class Overview

### 6.1 Main
The Main class is the application entry point. It initializes the student management system, creates the auto-save daemon thread, and displays the interactive console menu.

Responsibilities:
- Launch the system
- Display menu options
- Capture user input
- Route commands to the relevant operation
- Manage application exit behavior

### 6.2 StudentManagementSystem
This is the central controller class of the application. It manages all student, course, department, instructor, and enrollment data in memory.

Responsibilities:
- Add, update, search, and delete student records
- Add departments, instructors, and courses
- Enroll students in courses
- Record student marks
- Calculate GPA
- Save and load records
- Export transcripts asynchronously

### 6.3 Person
The Person abstract class represents common attributes for all people in the system, such as:

- ID
- Name
- Phone
- Email

It provides shared logic for validation and formatting while enforcing specific behavior through abstract methods.

### 6.4 Student
The Student class extends Person and adds academic-specific information:

- Semester
- Department

It also defines the role and description of a student.

### 6.5 Instructor
The Instructor class also extends Person. It stores:

- Designation
- Department

This class is responsible for identifying faculty members and their assigned department.

### 6.6 Department
The Department class stores department identifiers and names. It acts as a logical grouping for students and instructors.

### 6.7 Course
The Course class represents academic offerings with:

- Course ID
- Title
- Credit hours
- Assigned instructor

Validation checks ensure that credit values and course details remain valid.

### 6.8 AcademicRecord
The AcademicRecord abstract class provides a record-based structure for academic entries. It includes:

- Record ID
- Grade description behavior
- Grade point calculation contract

### 6.9 Enrollment
Enrollment is a concrete subclass of AcademicRecord and links a student to a course. It tracks the mark and calculates the final grade and GPA contribution.

### 6.10 DataManager
DataManager handles all file input/output operations. It reads and writes records in simple pipe-delimited text files stored in the data folder.

Files used:
- departments.txt
- students.txt
- instructors.txt
- courses.txt
- enrollments.txt

### 6.11 AutoSaveTask
This class implements the Runnable interface and runs in a background daemon thread. It periodically saves the system data to disk without disrupting the main application flow.

---

## 7. Data Persistence
Data persistence is implemented using text files stored in the src/data directory. This approach keeps the project simple and easy to understand without requiring a database connection.

Each data file stores structured records using a pipe-separated format, such as:

- Department: departmentId|departmentName
- Student: id|name|phone|email|departmentId|semester
- Course: courseId|title|credit|instructorId
- Enrollment: recordId|studentId|courseId|mark

This file-based system allows records to be saved and loaded automatically when the application starts.

---

## 8. GPA and Grading System
The project includes a grading system that evaluates marks into letter grades and grade points. Enrollment records convert numeric marks into grade categories such as A+, A, B, C, D, and F.

The GPA is computed using:

GPA = total grade points / total credit hours

This is implemented in the StudentManagementSystem class using enrolled courses and their credits.

---

## 9. Multithreading Features
The project includes two threaded operations:

1. Auto-save thread
   - Saves the application data at regular intervals
   - Prevents data loss during long sessions

2. Transcript export thread
   - Exports student transcripts in the background
   - Allows the user to continue working without interruption

This demonstrates a practical use of Java concurrency in a real-world project.

## 10. Input and Output Flow
The application uses a console-based menu where users interact using keyboard input. A typical workflow is:

1. User selects an option from the main menu
2. The program requests required data
3. The system verifies the input and relationships
4. Data is stored in memory and then saved to disk
5. Output is displayed to the user in plain text

This simple interaction model keeps the project easy to use and easy to test.

## 12. Limitations and Future Enhancements
Although the project is successful for a learning environment, it has some limitations:

- Command-line interface only
- No database backend
- Limited validation for cross-field integrity
- No authentication or role-based access
- No graphical user interface

### Possible enhancements:
- Add JavaFX or Swing GUI
- Use MySQL or SQLite for database storage
- Add login and admin/student roles
- Implement semester-wise course registration
- Generate PDF transcripts
- Add search, sorting, and filtering options
- Support course prerequisites and timetable management
